# Bridgeway front end

Static HTML, CSS, and JavaScript. No build step or framework is required.

## Workflow authority

Read `AGENTS.md` before changing role behavior. The host company accepts or rejects internship applications. Supervisors review training reports, not hiring decisions. Applying stays pending until a company decision; company-submitted evaluations are read-only for supervisors. Historical documents and backups may contain superseded rules.

## Run

Start Live Server from the project root and open `index.html`. It redirects to the homepage while preserving the query string and section hash. Alternatively, run `python -m http.server 8080 --bind 127.0.0.1` from this directory and visit http://127.0.0.1:8080/.

## Structure

```
index.html                      Small homepage entry point
<original-page-name>.html        Small redirects for existing URLs/bookmarks
pages/<page-name>/               Exactly three files per page
  <original-page-name>.html      Page content and links
  <page-name>.css                Page-specific presentation
  <page-name>.js                 Page-specific logic and event handlers
shared/css/                     Common styles, navigation, and interactions
shared/js/                      Portal model, behavior, navigation, and effects
shared/data/                    Existing JSON reference/demo data
assets/                         Original logo and reusable media
docs/                           Specifications and historical reports
docs/screenshots/               Historical screenshots
tools/check-site.mjs             Structure, syntax, and link validation
tools/compact-css.mjs            Safe one-rule-per-line CSS formatting
tools/refactor-site.mjs          One-time migration utility; do not rerun
```

The homepage uses `pages/home/index.html`, `home.css`, and `home.js`. Other pages retain their original HTML filenames, keeping existing filename-based behavior and saved card-order keys compatible.

## Editing

- Change a single page in its own folder. Shared appearance and behavior belong in `shared`.
- Page links use `../<other-page>/<original-name>.html`; shared files and assets use `../../shared/` and `../../assets/`.
- External JavaScript URLs are document-relative. Keep this convention for links generated by shared scripts.
- Keep stylesheet/script order: base → portal → navigation → enhancements → interactions, with page files at their existing extension points. Company dashboard has its own navigation logic.
- `data-style` identifies deduplicated page presentation. `data-presentation` preserves existing shared responsive/type rules; `data-onclick` connects explicit event handlers to their elements.
- CSS uses one rule per line with indented media queries. JavaScript stays readable rather than being minified.
- Dark mode, reduced-motion support, bridge animation, card arrangement, forms, and existing internship stages are retained. This remains the same front-end demo, not a new backend or authentication system.

## Validate

Run `node tools/check-site.mjs`. It checks every page folder, JavaScript syntax, local HTML/CSS references, and document-relative JavaScript page routes. Also test changed interactions in the browser.

All original flat page URLs redirect to their matching `pages/` destination, preserving query parameters and section hashes. Edit the actual pages inside `pages/`; root HTML files are compatibility entry points. Historical reports in `docs` may mention the previous flat layout.
